# Prompt 220 — Post-Release Tech Debt and Roadmap Plan

**Mode:** PLAN

## Objective
Prevent release-week triage from becoming permanent architecture debt.

## Build from audited evidence
Create post-release tracks for:
- API 36/framework/native follow-up if deferred;
- dependency modernization that was deliberately postponed;
- automated tests/regression coverage;
- voice/AI evaluation and agentic rollout;
- performance/reliability;
- security/privacy hardening;
- analytics/observability;
- documentation gaps;
- UX/accessibility debt;
- backend/data cleanup that requires staged migration.

Rank by impact, risk, dependency and reversibility. Do not invent delivery dates unless the owner requests scheduling.
